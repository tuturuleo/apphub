# AppHub

Единое место для прототипов на бесплатных тарифах. Выбираешь рецепт — AppHub создаёт репозиторий,
базу и сервис у провайдеров, связывает их секретами и настраивает деплой через GitHub Actions.
Дальше `git push` → автодеплой, а статусы всех частей проекта видны на одной странице.

Сам AppHub тоже живёт бесплатно: Cloudflare Worker + D1.

[![Deploy to Cloudflare](https://deploy.workers.cloudflare.com/button)](https://deploy.workers.cloudflare.com/?url=https://github.com/tuturuleo/apphub)

Каждый разворачивает **свой** AppHub в своём аккаунте Cloudflare: токены ваших провайдеров хранятся только
в вашей базе D1, зашифрованные вашим ключом. Через чужие серверы они не проходят.

## Рецепты

| Рецепт | Что создаётся | Провайдеры |
|---|---|---|
| Сайт + API + SQLite | репо, Worker со статикой и `/api/*`, база D1, деплой с миграциями | GitHub, Cloudflare |
| Сайт + Postgres | проект Supabase (Postgres + анонимный вход + RLS), Pages, миграции через Supabase CLI в Actions | GitHub, Supabase |
| Docker-сервис + Postgres | сервис в Docker на Render (шаблон — Python/FastAPI), база в Supabase, миграции при старте | GitHub, Render, Supabase |
| Сайт из Google-таблицы | публичное репо, GitHub Pages, пересборка по расписанию — из опубликованного CSV или приватной таблицы Drive | GitHub (+ Google) |

**Доступность из России.** С июня 2025 российские провайдеры ограничивают трафик к Cloudflare, поэтому сайты на
`workers.dev` (и на своих доменах за Cloudflare) без VPN могут не открываться. GitHub Pages, Supabase и Render
открываются. У рецептов есть пометка, а настройка «Пользователи в России» (страница «Новый проект») поднимает
доступные рецепты наверх — её учитывают и MCP, и ассистент (`recommended` в `list_recipes`).

Рецепт = шаблон кода в `templates/<id>` + описание в `src/worker/recipes/<id>.ts`.
В шаблонах `%%VAR%%` подставляется при создании проекта, `_github` и `_gitignore` становятся `.github` и `.gitignore`.

## Локальный запуск

```bash
npm install
npm run setup:local   # .dev.vars с ключом шифрования + миграции локальной D1
npm run dev           # http://localhost:5179
```

Локально вход отключён (`DEV_ALLOW_NO_AUTH=true` в `.dev.vars`), но подключения и рецепты
работают с настоящими API GitHub и Cloudflare — проекты создаются по-настоящему.

Локальный workerd не умеет ходить через прокси, поэтому в dev запросы к API провайдеров идут через
ретранслятор в Vite (`vite-dev-egress.ts`). Он берёт прокси из `HTTPS_PROXY` или из системных настроек macOS:
VPN в режиме системного прокси (Hiddify и т. п.) подхватывается сам, перезапуск при его включении не нужен.

## MCP: управление через Claude

AppHub отдаёт свои операции как MCP-сервер по адресу `/mcp` (Streamable HTTP, без сессий):

| Инструмент | Что делает |
|---|---|
| `list_recipes` | рецепты, их параметры и недостающие подключения |
| `list_connections` | подключённые провайдеры (без токенов) |
| `list_projects` / `get_project` | проекты; ресурсы со статусами, запуски Actions с логами, журнал |
| `create_project` | создаёт проект по рецепту и ждёт окончания создания |
| `get_project_files` | список файлов репозитория проекта или содержимое выбранных |
| `update_project_files` | один коммит: создать, заменить, удалить файлы; push запускает деплой |
| `deploy_project` | запускает деплой в GitHub Actions |
| `check_projects` | проверяет все проекты сейчас, открывает и закрывает алерты |
| `wake_resource` | действие над ресурсом: разбудить Supabase, включить отключённые workflow |

Удалять через MCP нельзя. Токены провайдеров подключаются только в интерфейсе.

**Claude Code, локально.** В репозитории лежит `.mcp.json` с `http://localhost:5179/mcp`: запустите `npm run dev`
и откройте Claude Code в этой папке — он предложит подключить сервер `apphub`. В другом проекте:

```bash
claude mcp add --transport http apphub http://localhost:5179/mcp
```

**Задеплоенный apphub.** `/mcp` закрыт токеном. Создайте его на странице «Безопасность» (показывается один раз)
и подключите — точная команда появится там же:

```bash
claude mcp add --transport http apphub https://apphub.<поддомен>.workers.dev/mcp \
  --header "Authorization: Bearer ah_…"
```

Коннекторы claude.ai требуют OAuth — это следующий шаг.

## Свой AppHub

**Кнопкой (проще всего).** Нажмите «Deploy to Cloudflare» выше. Cloudflare скопирует репозиторий в ваш GitHub,
создаст базу D1 и спросит два секрета:

- `ENCRYPTION_KEY` — ключ шифрования токенов: вывод `openssl rand -base64 32` или любая случайная фраза
  от 32 символов. Не меняйте его потом — сохранённые токены перестанут читаться.
- `SETUP_CODE` — код установки для первого passkey. Сохраните его в менеджере паролей.

Поля Build command и Deploy command: `npm run build` и `npm run deploy`. Если `npm run deploy` в поле показан
серым — впишите его явно: именно он применяет миграции базы, иначе AppHub откроется без таблиц. Секреты, если
форма подставила примеры, замените своими — AppHub примеры не примет. Дальше каждый push в ваш репозиторий —
новый деплой.

Один AppHub на аккаунт Cloudflare: имя Workflow (`apphub-provision`) уникально в пределах аккаунта.

**Вручную:**

```bash
npx wrangler login
npx wrangler d1 create apphub                    # database_id → wrangler.jsonc
openssl rand -base64 32 | npx wrangler secret put ENCRYPTION_KEY
openssl rand -base64 18 | tee /dev/stderr | npx wrangler secret put SETUP_CODE   # сохраните код
npm run deploy                                   # сборка, миграции, деплой
```

**Первый вход.** Откройте адрес Worker, введите код установки и создайте passkey (Touch ID, Face ID,
Windows Hello или ключ). Дальше вход — только по passkey. Код нужен снова, чтобы добавить passkey на новом
устройстве или на другом адресе (прокси). Забыли код — задайте новый: `npx wrangler secret put SETUP_CODE`;
passkey и данные не пострадают.

**Потом:** подключите провайдеров на странице «Подключения», откройте «Проекты» — AppHub добавит туда себя.
Для Claude Code создайте токен на странице «Безопасность». Если `workers.dev` у вас не открывается — там же
«Доступ без VPN».

## AppHub в своих проектах

Развёрнутый AppHub показывает себя в списке проектов: Worker, база D1 и прокси на Render под тем же
мониторингом и уведомлениями, что и остальные проекты. Нужен подключённый аккаунт Cloudflare, в котором живёт
Worker (адрес вида `<имя>.<поддомен>.workers.dev`). Удалить этот проект изнутри AppHub нельзя.

## Доступ без VPN

Если `workers.dev` недоступен, на странице «Безопасность» → «Доступ без VPN» AppHub создаст в вашем аккаунте
Render бесплатный прокси (Caddy из готового образа). Он пересылает запросы на Worker и подписывает их секретом;
только с ним AppHub верит адресу onrender.com. На новом адресе добавьте passkey с кодом установки.

## Вход

- Один владелец, вход по passkey (WebAuthn). Сессия — cookie `HttpOnly`, `Secure`, `SameSite=Lax` на 30 дней;
  в базе только хеш. Изменяющие запросы с cookie принимаются только с адреса самого AppHub (проверка `Origin`).
- MCP и скрипты — токены `ah_…` в заголовке `Authorization: Bearer`. В базе — хеши, отозвать можно в любой момент.
- Passkey привязан к адресу. Если открывать AppHub через другой адрес (прокси для доступа без VPN), добавьте там
  отдельный passkey с кодом установки. Адресу из `X-Forwarded-Host` AppHub верит, только если прокси прислал
  секрет `PROXY_SECRET`.
- Дополнительно можно поставить перед AppHub Cloudflare Access: задайте переменные Worker `ACCESS_TEAM_DOMAIN`
  (`<команда>.cloudflareaccess.com`) и `ACCESS_AUD` — в `vars` в `wrangler.jsonc` или в настройках Worker
  в панели Cloudflare. Тогда его JWT тоже принимается.
- Локально вход отключён `DEV_ALLOW_NO_AUTH=true` в `.dev.vars`; в развёрнутом AppHub этой переменной нет.

Создание идёт в фоне: `POST /api/projects` записывает проект, `POST /api/projects/:id/provision` запускает
Cloudflare Workflow (`src/worker/workflow.ts`) и сразу отвечает. Workflow доводит создание до конца, даже если
вкладка закрыта или MCP-клиент перестал ждать. Проект, застрявший в «Создаётся» (процесс оборвался), сам
переходит в «Ошибка», чтобы его можно было удалить и пересоздать.

**Удаление.** «Удалить проект и ресурсы» стирает у провайдеров сервисы Render и Workers, базы D1 и Supabase,
репозиторий (вместе с Pages) — в обратном порядке создания — и затем проект в apphub. Если что-то удалить не вышло,
проект остаётся с оставшимися ресурсами и удаление можно повторить. Через MCP удалять нельзя.

## Ассистент в интерфейсе

Страница «Ассистент» — чат с Claude (Opus 5.5) с теми же инструментами, что у MCP: «разверни сайт с базой для
списка покупок», «почему упал деплой у notes?». Перед изменениями ассистент спрашивает согласия. Нужен ключ
Claude API (подключение «Claude API»); подписка Claude его не даёт — без ключа AppHub доступен из Claude Code через MCP.
Инструменты описаны один раз в `src/worker/tools.ts` и используются и MCP-сервером, и чатом.

## Мониторинг и уведомления

Раз в 10 минут (Cron Trigger в `wrangler.jsonc`) apphub проверяет все проекты теми же проверками, что и интерфейс,
и ведёт список активных проблем:

- упал деплой в GitHub Actions — со ссылкой на лог;
- ресурс в ошибке (сайт не отвечает и т.п.);
- проект Supabase уснул — кнопка «Разбудить»;
- GitHub отключил workflow из-за неактивности репозитория — кнопка «Включить».

В Telegram приходят только изменения: новая проблема и её исправление. Ошибка самой проверки (сеть, лимиты API)
проблемой ресурса не считается. Бот подключается на странице «Подключения».

Cron срабатывает только у задеплоенного Worker. Локально — кнопка «Проверить сейчас», инструмент MCP `check_projects`
или `curl "localhost:5179/cdn-cgi/handler/scheduled"`.

## Каталог ресурсов и аккаунты

Ресурсы живут отдельно от проектов: страница «Ресурсы» показывает все репозитории, базы, сервисы и таблицы — со
статусом, аккаунтом, происхождением и проектами, к которым они привязаны. Ресурс можно привязать к нескольким проектам.

- **Происхождение:** создан AppHub · импортирован («Найти в аккаунте» — существующие репозитории, базы D1 и Supabase,
  Workers, сервисы Render, таблицы Drive) · внешний («Добавить свою базу» — Postgres по строке подключения, хранится
  зашифрованной, AppHub проверяет доступность сервера).
- **Удаление проекта** удаляет у провайдера только созданное AppHub и больше никому не нужное; остальное отвязывает.
  Импортированные и внешние ресурсы AppHub у провайдера не удаляет никогда.
- **Несколько аккаунтов** одного провайдера: при создании проекта выбирается аккаунт для каждого провайдера,
  лимиты считаются по аккаунтам. Служебные подключения (Telegram, Claude API) — по одному.

## Конструктор проекта

Рецепт «Собрать самому» создаёт пустой проект. На его странице:

- **Создать ресурс** — репозиторий GitHub, базу Supabase или D1, сервис Render из репозитория проекта (нужен
  Dockerfile), Telegram-бота (токен от @BotFather; AppHub следит, что бот жив). База Supabase и сервис Render
  создаются в фоне.
- **Привязать из каталога** — любой ресурс, в том числе общий для нескольких проектов.
- **Связи** — выход одного ресурса записывается в переменную другого: `DATABASE_URL` базы, `SUPABASE_URL` и
  публичный ключ, `TELEGRAM_BOT_TOKEN`, адрес сервиса или сайта → переменная окружения Render (с передеплоем),
  секрет Worker или секрет GitHub Actions. «Передать заново» переписывает все связи (например, после смены пароля).

Строку подключения новых баз Supabase AppHub хранит зашифрованной; для баз, созданных раньше, её можно задать в
каталоге. Те же операции есть в MCP: `add_project_resource`, `bind_resource`, `connect_resources`.

## Одна база для нескольких проектов

Базу Postgres (Supabase или свою) можно привязать к нескольким проектам. При привязке выбирается режим:

- **Изолированно** (по умолчанию) — AppHub создаёт в базе схему `p_<проект>` и пользователя с правами только на неё
  и `search_path` на свою схему. Проект не видит чужих данных, его данные не видят другие. `DATABASE_URL` в связях
  отдаёт строку этого пользователя (для пулера Supabase — `роль.ref`). Отвязка и удаление проекта удаляют его схему
  и пользователя; остальная база не затрагивается.
- **Общие данные** — полный доступ к базе, для приложений над одними данными.

SQL выполняется прямо из Worker по TCP (postgres.js, флаг `nodejs_compat`) админской строкой подключения базы, поэтому
она должна быть задана в каталоге. Из локальной сети с ограничениями TLS-соединение с пулером Supabase может не
устанавливаться — тогда проверяйте на задеплоенном apphub.

## Google Drive

Подключение по JSON-ключу сервисного аккаунта Google: он видит только таблицы, которыми поделились с его почтой.
Рецепт «Сайт из Google-таблицы» умеет брать данные из такой приватной таблицы — без «Опубликовать в интернете»:
таблица выбирается из списка, сборка в Actions читает её через Drive API (ключ — в секрете `GOOGLE_SA_KEY`).
Таблица — ресурс проекта: мониторинг предупредит, если доступ к ней пропал. При удалении проекта таблица остаётся.

## Лимиты бесплатных тарифов

Страница «Лимиты» (и MCP-инструмент `get_limits`) показывает «занято / доступно» по подключённым провайдерам:
активные проекты Supabase (2), базы D1 (10) и их объём (5 ГБ), Workers (100) — посчитано через API; часы Render,
запросы Workers и минуты Actions — известный лимит со ссылкой на страницу потребления (их API не отдаёт).
Рецепт, которому не хватит лимита, AppHub не даст создать — с объяснением, кто занимает. Мониторинг пишет в Telegram,
когда лимит почти (≥80%) или полностью исчерпан и когда снова есть запас.

## Безопасность

- Токены провайдеров шифруются AES-256-GCM ключом `ENCRYPTION_KEY` и не возвращаются в интерфейс.
- Токен Cloudflare кладётся в секреты каждого созданного репозитория, чтобы Actions могли деплоить.
  Давайте ему только права из инструкции на странице «Подключения».
- Токен Supabase остаётся в apphub. В репозиторий уходит только строка подключения к базе конкретного проекта.
- «Убрать из AppHub» не удаляет ресурсы у провайдеров.

## Структура

```
src/worker/            API на Hono
  providers/           клиенты GitHub и Cloudflare, каталог провайдеров
  recipes/             рецепты и загрузка шаблонов
  engine.ts            выполнение рецептов, статусы ресурсов
  service.ts           операции с проектами, общие для REST и MCP
  tools.ts             инструменты для LLM: общие для MCP и чата
  mcp.ts               MCP-сервер
  chat.ts              ассистент на Claude API
  monitor.ts           мониторинг проектов и уведомления в Telegram
  limits.ts            лимиты бесплатных тарифов
  catalog.ts           каталог: поиск в аккаунтах, импорт, внешние ресурсы
  builders.ts          создание отдельных ресурсов в проекте
  wiring.ts            связи: выходы ресурсов → переменные других ресурсов
  sharing.ts           привязка ресурсов, режимы общей базы
  isolation.ts         схема и пользователь проекта в общей базе (SQL через postgres.js)
  workflow.ts          фоновое создание ресурсов (Cloudflare Workflows)
  sealed-box.ts        шифрование секретов GitHub Actions (libsodium sealed box)
src/web/               интерфейс на React
templates/             шаблоны проектов, встраиваются в бандл Worker
migrations/            схема D1 самого apphub
```
